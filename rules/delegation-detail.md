# Delegation detail

Part of [`rules/delegation.md`](delegation.md), with its authority and precedence.

| Rule | Text |
|---|---|
| Merge | A thread reviews, corrects and merges its own PR with no person in the loop. One reviewer with a fresh context reads the head commit, the thread corrects, one check reads the corrections, and a squash merge follows once every check and CI are green. [`skills/merging`](../skills/merging/SKILL.md) has the steps |
| Question | Only a billing question, a vision question or a critical website decision reaches the owner. It goes through the orchestrator as one decision card, after research, with options and a recommendation. A thread decides and executes everything else |
| Link | Every action the owner must take goes in the main chat with a direct link to the exact place. That covers a yes, an Allow, something to copy or paste, and a quick click. Never send the owner into a thread or a browser tab |
| Outside company | Another owner's template is read and pinned, never written to: no push, PR, issue or card there. Link what is shared and copy none of it |

## Authority

The owner asked for these rules in their own chat on 2026-11-25:

> "Git Crafter's template is wrong. It should be merging. It's autonomous development. There should be no person in the loop. The agents need to review and correct, and they need to do it well."

The same chat added a second rule. A step only the owner can take, such as a yes, an Allow click, a copy or a paste, goes in the main chat with its link.
